# 模块详细设计说明书

## 一、文档目的

本说明书旨在对“智慧植物灌溉与监控系统”中的关键功能模块进行逐一详细分析，明确其输入输出、功能职责、逻辑结构、状态转换、数据结构与接口规范，确保各模块具备良好的可实现性、可维护性与可测试性。本章节将针对 STM32 模块与 ESP32 模块进行完整的子模块详细设计说明。

## 二、STM32 传感控制模块（详细设计）

### 2.1 模块定位

STM32 作为智慧灌溉系统的底层硬件主控平台，负责环境数据的底层采集、数据预处理、灌溉控制执行及与中继设备（ESP32）的低延迟串口通信，具有高实时性与稳定性要求。

### 2.2 硬件接口

- DHT11：温湿度传感器 → GPIO
- 模拟土壤湿度传感器 → ADC1
- 光敏电阻模块 → ADC2
- 超声波水位检测模块 → GPIO + 定时器输入捕获
- 电量检测模块（分压）→ ADC3
- 水泵控制继电器 → GPIO 输出
- 按键（人工触发） → GPIO 外部中断
- UART 通信模块 → USART1/2

### 2.3 功能结构

- **传感器数据采集子模块**
  - 每 5 秒进行一次 ADC/DHT 轮询，使用 DMA 加速通道
  - 所有数据按统一结构体封装至缓冲区
- **控制逻辑子模块**
  - 根据预设阈值判断是否自动触发灌溉
  - 接收 ESP32 命令后立即执行灌溉过程
- **通信子模块**
  - 使用 HAL UART 中断/缓冲区模式双向通信
  - 上报传感器数据 JSON 串，接受 JSON 控制命令

### 2.4 状态机设计

```
[初始化] → [采集中] → [判断是否灌溉]
                         ↓        ↑
                    [执行灌溉] ← [等待命令]
```

### 2.5 数据结构（定义于 sensor.h）

```
typedef struct {
  float temperature;
  float humidity;
  float soil_moisture;
  uint16_t light_level;
  uint8_t water_low;
  uint8_t battery_percent;
  char timestamp[20];
} SensorFrame;
```

### 2.6 数据上传协议（JSON 示例）

```
{
  "device_id": "stm32-a01",
  "temp": 25.6,
  "humidity": 51.2,
  "soil": 17.3,
  "light": 812,
  "water": "normal",
  "battery": 88,
  "timestamp": "2025-06-13 17:42:10"
}
```

### 2.7 灌溉控制逻辑

- 当 `soil_moisture < min_threshold` 且 `water_low == 0` 时触发灌溉
- 控制继电器高电平持续 5 秒
- 灌溉行为完成后记录本地日志并上报状态

### 2.8 本地异常处理逻辑

| 异常情形      | 应对策略                      | 上报字段           |
| ------------- | ----------------------------- | ------------------ |
| 无水位        | 停止灌溉，提示缺水            | `error_code = 101` |
| 电压过低      | 降低采样频率，关闭灌溉        | `error_code = 102` |
| UART 通信失败 | 重启 UART 模块，最大尝试 3 次 | `error_code = 103` |

### 2.9 模块间调用关系

```
采集模块(sensor.c) → 数据封装(sensor_frame.c)
               ↓                          ↑
控制模块(control.c) ← 命令接收(comm_uart.c)
```

### 2.10 可测试性说明

- 启动 Debug 模式后，通过串口工具可验证：
  - JSON 输出格式合法性
  - 灌溉控制行为是否符合阈值逻辑
- 使用 GPIO 指示灯辅助调试：采集绿灯闪烁，灌溉红灯常亮

## 三、ESP32 中继与交互模块（详细设计）

### 3.1 模块定位

ESP32 模块位于系统结构的中间层，承担与 STM32 的底层数据通信、中间数据解析处理与上传、状态显示（OLED、LED）、语音交互管理、远程控制接收与转发等职责，是系统的边缘感知与人机交互中枢。

### 3.2 硬件与接口说明

- UART 接口（连接 STM32）
- OLED 显示屏（I2C）
- WS2812 灯带（单线 GPIO）
- 麦克风模块（I2S 或模拟输入）
- 按键（本地模式切换）
- ESP-NOW/WIFI（连接路由器/服务器）

### 3.3 功能子模块划分

| 子模块       | 职责                     | 描述                       |
| ------------ | ------------------------ | -------------------------- |
| 串口监听任务 | 接收 STM32 上传数据      | 并转发至服务器和树莓派     |
| 控制命令接收 | 接收平台命令并转发 STM32 | 包括灌溉、阈值设置等       |
| 显示管理     | OLED 状态轮播、图标更新  | 基于系统模式变化刷新屏幕   |
| LED 状态指示 | 根据状态变化显示颜色     | 电量、浇水、异常等多种状态 |
| 语音管理     | 录音+命令识别+AI对话     | 联动本地逻辑与云端接口     |

### 3.4 多任务调度逻辑（FreeRTOS）

- `UartTask`：循环接收 STM32 的数据 → 入 JSON 队列
- `UploadTask`：定时取出 JSON → 封包上传 HTTP/MQTT
- `OLEDTask`：根据模式轮询切换显示内容（默认、灌溉、语音）
- `LEDTask`：根据 soil、battery 状态控制 RGB 编码
- `VoiceTask`：监听按钮或语音唤醒词，激活录音与处理逻辑

### 3.5 状态机（工作模式切换）

```
[default] --(voice/button)--> [watering]
   |                              |
   +--------<-- timeout ----------+
   |
   +--------(low battery)-------> [low_power]
```

### 3.6 通信数据格式（示例 JSON）

```
{
  "device_id": "esp32-a01",
  "status": "watering",
  "voice_mode": true,
  "threshold": {
    "min_moisture": 20,
    "max_moisture": 40
  },
  "relay_status": "on"
}
```

### 3.7 异常与调试机制

| 异常类型           | 响应策略        | LED 指示   |
| ------------------ | --------------- | ---------- |
| 无法连接 WIFI      | 自动重连（3次） | 蓝色闪烁   |
| 接收 JSON 解析失败 | 丢弃并记录日志  | 红灯短闪   |
| 与 STM32 通信超时  | 重启串口模块    | 黄色持续亮 |

### 3.8 可测试性说明

- 使用串口助手模拟上位机调试数据流动
- 模拟按钮事件触发不同工作模式，观察 OLED、LED 是否变化正确
- 打印系统日志、上传日志、出错记录
- 在 Voice 模块中测试唤醒与异常退出情况

## 四、树莓派 AI 控制模块（详细设计）

### 4.1 模块定位

树莓派作为本系统中的边缘智能中心，运行 PPO 强化学习模型，根据环境状态数据生成最优灌溉策略，并通过无线通信将阈值或控制指令反馈至 ESP32 模块。该模块的设计需兼顾实时性、学习能力与模型可解释性。

### 4.2 算法结构

采用近端策略优化算法（Proximal Policy Optimization, PPO），基于策略梯度方法构建 Actor-Critic 网络架构：

- **Actor 网络**：根据当前状态输出连续浇水量（0~1）
- **Critic 网络**：评估当前策略下状态的长期收益（Value Function）

模型部署结构如下：

```
状态输入 → 策略网络（Actor） → 浇水量预测 → 策略阈值转换
                     ↓
              价值网络（Critic） → 更新信号
```

### 4.3 状态空间设计（State Space）

| 状态变量        | 含义               | 取值范围   |
| --------------- | ------------------ | ---------- |
| soil_moisture   | 当前土壤湿度       | [0.0, 1.0] |
| temperature     | 空气温度           | [10, 45] ℃ |
| humidity        | 空气湿度           | [0, 100]%  |
| light_intensity | 光照强度（归一化） | [0.0, 1.0] |
| co2_level       | CO₂ 浓度（模拟）   | ppm, float |
| growth_stage    | 植物生长进度       | [0.0, 1.0] |

状态向量为 6 维连续变量，输入策略网络。

### 4.4 动作空间（Action Space）

动作为连续浇水量：

```
Action ∈ [0.0, 1.0]  // 表示相对最大浇水量（如200ml）
```

### 4.5 奖励函数设计

```
Reward = α * Growth_Reward + β * Moisture_Reward - γ * Water_Penalty
```

- Growth_Reward：与生长速度成正比
- Moisture_Reward：土壤湿度处于 [0.4, 0.6] 区间获得正奖
- Water_Penalty：每单位水施加惩罚以控制资源浪费

超参数示例：α=1.0，β=0.6，γ=0.2

### 4.6 策略输出与下发

策略输出形式：

```
{
  "strategy_id": "ppo-v3.2-202506",
  "threshold": {
    "min_moisture": 0.38,
    "max_moisture": 0.62
  },
  "confidence": 0.91
}
```

ESP32 接收到该策略后用于动态更新本地判断逻辑。

### 4.7 模型训练与部署流程

1. 收集历史数据（湿度、光照、灌溉记录、植物状态）
2. 构造模拟环境（Gym-like）
3. 使用 PPO 训练智能体
4. 导出模型权重 `.pt/.onnx` 文件
5. 树莓派部署推理引擎（如 PyTorch、ONNXRuntime）
6. 每日定时推理 → 输出阈值 → 发回 ESP32

### 4.8 模型更新与版本控制

| 字段        | 描述                         |
| ----------- | ---------------------------- |
| strategy_id | 模型版本编号（自动生成）     |
| train_date  | 最近训练时间                 |
| performance | 策略成功率评估               |
| reward_mean | 平均奖励值（跨episode）      |
| file        | 模型路径（如 model_v3.2.pt） |

所有策略输出需绑定 metadata，可回溯。

### 4.9 异常与安全处理

- 若模型输出超出物理可行范围（如阈值 > 1.0）→ 回滚至默认策略
- 若连续多次无法完成模型推理 → 自动关闭 AI 接口，转为手动/规则控制
- 日志记录所有推理请求、输出、奖励与执行效果（JSON + CSV）

### 4.10 可测试性说明

- 使用仿真环境验证训练策略的稳定性与收敛性
- 使用历史数据复现实际推理流程，校验策略效果
- 所有策略下发结果需可视化呈现（图表+日志）

## 五、Web 前端与后端模块（详细设计）

### 5.1 模块定位

Web 前后端模块为系统的远程可视化平台与用户交互界面，主要负责：

- 实时/历史数据展示；
- 灌溉控制与策略参数设置；
- 多设备管理与用户权限控制；
- 与树莓派/ESP32 进行 HTTP/MQTT 通信。

该模块采用前后端分离架构，前端基于 Vue.js 框架，后端使用 Flask（Python）构建。

### 5.2 前端架构设计

#### 5.2.1 技术栈

- 框架：Vue.js 3 + Vite
- UI 组件库：Element Plus + ECharts
- 状态管理：Pinia
- 路由管理：Vue Router
- 网络请求：Axios（封装 API 调用）

#### 5.2.2 页面设计

| 页面       | 功能说明                             |
| ---------- | ------------------------------------ |
| 登录页     | 用户登录/注册、Token 获取            |
| 控制台     | 展示植物状态、策略控制、实时反馈图表 |
| 历史数据页 | 支持时间区间查询与多维指标可视化     |
| 策略页     | 当前策略查看与修改、AI推荐策略接入   |
| 用户中心   | 多设备管理、权限绑定、偏好设置       |

#### 5.2.3 数据展示

- 使用 ECharts 展示：
  - 湿度/温度/光照变化曲线
  - 灌溉行为时间轴
  - AI 策略触发记录图

### 5.3 后端系统设计

#### 5.3.1 技术栈

- 框架：Flask + Gunicorn + Nginx
- 数据库：MySQL + SQLAlchemy
- API 风格：RESTful + JSON 数据格式
- 权限认证：JWT + OAuth2（可拓展）
- 模块组织：Blueprints + 分层 MVC 架构

#### 5.3.2 数据库设计

| 表名            | 字段                                          | 描述             |
| --------------- | --------------------------------------------- | ---------------- |
| users           | id, username, password, email, role           | 用户信息         |
| devices         | id, user_id, name, location, status           | 设备与植物元数据 |
| data_logs       | id, device_id, timestamp, soil, temp, light   | 实时数据记录     |
| irrigation_logs | id, device_id, start_time, duration           | 灌溉行为日志     |
| ai_strategies   | id, device_id, model_id, timestamp, threshold | AI 策略记录      |

#### 5.3.3 API 接口示例

```
GET /api/device/<id>/data
POST /api/device/<id>/irrigate
POST /api/user/login
GET /api/strategy/current
POST /api/strategy/manual-update
```

#### 5.3.4 模块职责

| 模块     | 描述                        |
| -------- | --------------------------- |
| auth     | 用户身份认证，Token 管理    |
| data     | 数据上传与下发、缓存管理    |
| strategy | AI 策略管理、接口桥接树莓派 |
| notify   | 灌溉通知与系统异常报警      |

### 5.4 通信接口与部署逻辑

#### 5.4.1 与 ESP32 通信

- 使用 HTTP/HTTPS 协议，ESP32 定时上传 JSON 数据包
- Flask 提供 `/api/device/report` 接口解析数据并存入数据库

#### 5.4.2 与树莓派通信

- 使用 MQTT 或 REST API 通信
- 每日推送 AI 建议策略：`POST /api/strategy/ai`
- 提供策略查询接口供前端展示

#### 5.4.3 系统部署架构

```
用户浏览器 → Nginx（反向代理）
                  ↓
           Gunicorn + Flask
                  ↓
               MySQL DB
               + 日志文件
```

支持部署于树莓派本地，或远程服务器。

### 5.5 异常与安全机制

| 异常类型             | 应对措施                           |
| -------------------- | ---------------------------------- |
| 数据包字段缺失       | 返回 400 错误并记录日志            |
| Token 过期/伪造      | 强制登出，返回 401 响应            |
| 用户操作越权         | 拒绝并返回 403 权限不足            |
| 后端崩溃或数据库断连 | 使用 Supervisor 自动重启，记录日志 |

### 5.6 可测试性说明

- 前端使用 Cypress/VitePress 编写自动化测试用例
- 后端使用 pytest + mock + coverage 进行接口回归测试
- 提供 Swagger 在线文档用于接口调试
- 所有数据表支持版本日志追踪（可恢复误操作）
