# 智慧浇水系统测试说明书

## 一、文档目的

本文档旨在系统化描述“智慧植物灌溉与监控系统”的测试计划与方法，确保系统满足《需求规格说明书》中提出的各项功能、性能与安全性指标，通过全面的测试过程确认系统稳定性、准确性与用户友好性，作为系统交付与验收的关键依据之一。

## 二、测试策略与方法

### 2.1 黑盒测试（Black-box Testing）

- 目的：从用户角度出发，不依赖系统内部结构，仅测试输入与输出行为。
- 范围：
  - 功能点是否符合需求；
  - 各模块输入边界值、非法输入是否能正确处理；
  - 用户界面交互逻辑是否清晰。

### 2.2 白盒测试（White-box Testing）

- 目的：依据程序内部逻辑设计测试用例，验证流程正确性与代码覆盖率。
- 范围：
  - 状态机转换完整性（如 OLED 模式切换）；
  - 函数调用覆盖、分支路径遍历（如灌溉控制逻辑、数据打包结构）；
  - 异常路径（如语音识别失败、串口接收异常）。

### 2.3 集成测试（Integration Testing）

- 验证各子模块（STM32、ESP32、树莓派、前后端）在系统联调状态下是否稳定协作。

### 2.4 回归测试

- 每次代码更新后执行核心功能测试，防止旧功能回退或出现 Bug。

## 三、测试项分类与目标

| 测试类型   | 目标                     | 示例功能                     |
| ---------- | ------------------------ | ---------------------------- |
| 功能测试   | 核心功能是否完整         | 自动灌溉、手动控制、数据展示 |
| 性能测试   | 响应时间/并发能力        | 数据上传频率、Web控制响应    |
| 安全性测试 | 数据与控制权限是否被保护 | JWT 验证、策略更新权限控制   |
| 兼容性测试 | 不同平台是否兼容         | 多浏览器、移动端适配         |
| 稳定性测试 | 长时间运行是否出错       | 72h 无断连、无死机           |
| 易用性测试 | 用户使用过程是否流畅     | 页面导航、按钮位置合理性     |

## 四、功能测试用例（Function Test Cases）

### TC-01 自动灌溉功能验证

- **输入**：soil_moisture = 12.5%，AI 设定阈值为 20%
- **操作**：STM32 发送数据 → ESP32 判断策略 → 控制灌溉
- **预期**：OLED 显示浇水界面，日志记录下发与执行动作
- **验证方式**：观察显示与日志；实测土壤含水率变化

### TC-02 用户手动控制按钮

- **输入**：前端用户点击“立即浇水”按钮
- **操作**：前端调用 REST API → ESP32 接收指令 → 控制水泵
- **预期**：OLED 状态切换、LED 点亮、灌溉开始

### TC-03 策略部署正确性

- **输入**：上传策略 JSON 文件（阈值为 [0.35, 0.65]）
- **操作**：Web → Flask 后端 → ESP32 同步策略
- **预期**：ESP32 本地策略参数更新，后续判断按新阈值执行

## 五、性能测试指标

| 测试项           | 目标值              | 测试方法                         |
| ---------------- | ------------------- | -------------------------------- |
| 灌溉触发响应时间 | ≤ 1.5 秒            | 时间戳对比：策略触发 → 灌溉执行  |
| AI 策略命中率    | ≥ 90%               | 湿度保持在推荐范围的比例         |
| 最大设备并发支持 | ≥ 10 个设备同时上传 | 多线程模拟设备上报               |
| 前端页面加载时间 | ≤ 2 秒              | Chrome Lighthouse + 网络限速模拟 |
| 系统稳定运行时间 | ≥ 72 小时           | 长时监测日志与内存消耗           |

## 六、测试环境配置

- **硬件**：STM32、ESP32、树莓派、传感器套件、服务器
- **软件环境**：
  - Python 3.10、Flask、PyTorch、Vue 3、MySQL
  - Pytest、Cypress、Postman、Wireshark
- **网络**：具备局域网与公网测试环境
- **测试工具**：
  - Postman（接口测试）
  - Cypress（端到端用户交互）
  - Grafana + MySQL（性能与行为监控）

## 七、测试结果记录与日志管理

- 每轮测试生成用例执行表格（Excel）与日志（JSON/CSV）
- 日志统一存放于 `logs/模块名/日期/` 目录下
- 所有结果支持图形可视化（Grafana）
- 每阶段测试后生成《测试总结报告》（Test Summary Report）

## 八、通过判定标准

| 维度         | 判定标准                                     |
| ------------ | -------------------------------------------- |
| 功能通过率   | ≥ 95%                                        |
| 策略稳定性   | 策略适配湿度控制在 40~60% 区间内准确率 ≥ 90% |
| 页面可用性   | 页面加载无卡顿、控制按钮响应及时             |
| 系统恢复能力 | 异常后可在 3 秒内恢复至稳定运行              |
| 用户体验评分 | ≥ 4.5/5（通过问卷调查或打分系统）            |

> 注：如某轮测试未通过，可进行缺陷分析，填报《缺陷记录单》，并进入再测试阶段。
