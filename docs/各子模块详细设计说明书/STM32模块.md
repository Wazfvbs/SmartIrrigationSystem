## STM32 传感控制模块

### 2.1 模块定位

STM32 作为智慧灌溉系统的底层硬件主控平台，负责环境数据的底层采集、数据预处理、灌溉控制执行及与中继设备（ESP32）的低延迟串口通信，具有高实时性与稳定性要求。

### 2.2 硬件接口

- DHT11：温湿度传感器 → GPIO
- 模拟土壤湿度传感器 → ADC1
- 光敏电阻模块 → ADC2
- 超声波水位检测模块 → GPIO + 定时器输入捕获
- 电量检测模块（分压）→ ADC3
- 水泵控制继电器 → GPIO 输出
- 按键（人工触发） → GPIO 外部中断
- UART 通信模块 → USART1/2

### 2.3 功能结构

- **传感器数据采集子模块**
  - 每 5 秒进行一次 ADC/DHT 轮询，使用 DMA 加速通道
  - 所有数据按统一结构体封装至缓冲区
- **控制逻辑子模块**
  - 根据预设阈值判断是否自动触发灌溉
  - 接收 ESP32 命令后立即执行灌溉过程
- **通信子模块**
  - 使用 HAL UART 中断/缓冲区模式双向通信
  - 上报传感器数据 JSON 串，接受 JSON 控制命令

### 2.4 状态机设计

```
[初始化] → [采集中] → [判断是否灌溉]
                         ↓        ↑
                    [执行灌溉] ← [等待命令]
```

### 2.5 数据结构（定义于 sensor.h）

```
typedef struct {
  float temperature;
  float humidity;
  float soil_moisture;
  uint16_t light_level;
  uint8_t water_low;
  uint8_t battery_percent;
  char timestamp[20];
} SensorFrame;
```

### 2.6 数据上传协议（JSON 示例）

```
{
  "device_id": "stm32-a01",
  "temp": 25.6,
  "humidity": 51.2,
  "soil": 17.3,
  "light": 812,
  "water": "normal",
  "battery": 88,
  "timestamp": "2025-06-13 17:42:10"
}
```

### 2.7 灌溉控制逻辑

- 当 `soil_moisture < min_threshold` 且 `water_low == 0` 时触发灌溉
- 控制继电器高电平持续 5 秒
- 灌溉行为完成后记录本地日志并上报状态

### 2.8 本地异常处理逻辑

| 异常情形      | 应对策略                      | 上报字段           |
| ------------- | ----------------------------- | ------------------ |
| 无水位        | 停止灌溉，提示缺水            | `error_code = 101` |
| 电压过低      | 降低采样频率，关闭灌溉        | `error_code = 102` |
| UART 通信失败 | 重启 UART 模块，最大尝试 3 次 | `error_code = 103` |

### 2.9 模块间调用关系

```
采集模块(sensor.c) → 数据封装(sensor_frame.c)
               ↓                          ↑
控制模块(control.c) ← 命令接收(comm_uart.c)
```

### 2.10 可测试性说明

- 启动 Debug 模式后，通过串口工具可验证：
  - JSON 输出格式合法性
  - 灌溉控制行为是否符合阈值逻辑
- 使用 GPIO 指示灯辅助调试：采集绿灯闪烁，灌溉红灯常亮
