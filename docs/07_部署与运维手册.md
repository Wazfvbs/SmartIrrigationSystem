# 智慧植物灌溉系统部署与运维手册

## 一、文档目的

本手册用于指导项目管理员、开发人员及维护人员对“智慧植物灌溉与监控系统”进行部署、配置、运行与维护操作，确保系统稳定、高效、可靠运行。涵盖初次部署、版本更新、模块替换、常规巡检与远程故障恢复等关键环节。

## 二、系统架构总览

系统采用模块化嵌入式结构 + 云边协同设计，主要由四大子系统组成：

| 子系统       | 描述                           |
| ------------ | ------------------------------ |
| STM32 控制层 | 基于传感器采集与灌溉控制电路   |
| ESP32 中继层 | 本地中转与用户交互控制枢纽     |
| 树莓派 AI 层 | 策略计算、模型训练与更新       |
| Web 控制层   | 数据可视化、远程控制与设备管理 |

系统整体通过 JSON 格式数据交互，并支持 MQTT 与 HTTP 协议混合传输。

## 三、部署准备

### 3.1 硬件准备

- STM32 + 土壤湿度、温湿度、光照传感器
- ESP32 + OLED + 麦克风模块 + LED 灯带
- 树莓派 4B（推荐 4G RAM 以上） + 电源 + SD卡 ≥ 32G
- 局域网路由器或公网服务器
- 水泵 + 水箱 + 电源模块 + 继电器

### 3.2 软件环境

| 模块     | 环境配置                                   |
| -------- | ------------------------------------------ |
| ESP32    | PlatformIO / Arduino IDE，ESP-IDF v5.0     |
| 树莓派   | Python 3.10，PyTorch，Flask，cron定时器    |
| 后端     | Python Flask + MySQL5.7 + Gunicorn + nginx |
| 前端     | Vue 3 + ECharts + Axios                    |
| 部署工具 | systemd / Supervisor / Docker（可选）      |

## 四、部署流程

### 4.1 树莓派部署

```
# 创建虚拟环境
python3 -m venv irrigation_env && source irrigation_env/bin/activate

# 安装依赖包
pip install -r requirements.txt

# 启动模型服务与 Flask API
python ai_infer.py &  # 强化学习推理服务
python web_api.py    # 与 ESP32 的策略交互接口
```

### 4.2 ESP32 编译与烧录

1. 使用 PlatformIO 导入项目目录
2. 配置 `wifi_config.h` 中路由器账号密码与服务器地址
3. 编译并烧录

```
pio run -t upload
```

### 4.3 后端服务器部署（可选公网）

```
# 安装依赖
pip install flask flask-cors pymysql

# 启动接口服务
gunicorn -w 4 -b 0.0.0.0:5000 app:app

# 若使用 nginx:
sudo cp nginx.conf /etc/nginx/sites-available/irrigation
sudo ln -s /etc/nginx/sites-available/irrigation /etc/nginx/sites-enabled
sudo systemctl restart nginx
```

### 4.4 前端编译与部署

```
cd frontend
npm install
npm run build  # 生成 dist 文件夹

# 部署至 nginx 静态目录
cp -r dist/ /var/www/html/irrigation
```

## 五、系统运行管理

### 5.1 日志监控

- Flask 后端日志：`logs/flask.log`
- 树莓派 AI 模型日志：`logs/ai_infer.log`
- ESP32 串口日志：PlatformIO Serial Monitor
- Web 用户行为日志：通过 MySQL + DataTables 可视化

### 5.2 模型更新

1. 在树莓派上训练新策略
2. 使用 `scp` 或 Web 页面上传 `.json` 文件
3. ESP32 定时拉取更新并更新阈值策略

### 5.3 数据备份策略

- 每日凌晨 3:00 自动导出历史数据表至 CSV
- 使用 `crontab` 设置定时任务：

```
0 3 * * * python backup_data.py > logs/backup.log
```

## 六、常规维护与巡检

| 周期   | 检查项     | 检查内容                         |
| ------ | ---------- | -------------------------------- |
| 每日   | 运行状态   | OLED 显示、数据刷新是否正常      |
| 每周   | 网络稳定性 | 树莓派 ping 网关/服务器测试      |
| 每月   | 水泵维护   | 水泵噪音、出水量、滤网清洁       |
| 每季度 | 模型优化   | 是否需重新训练策略，更新模型版本 |

## 七、故障诊断与恢复

| 故障现象     | 原因诊断            | 恢复操作                               |
| ------------ | ------------------- | -------------------------------------- |
| OLED 无响应  | 电源或 I2C 通信异常 | 检查接线/更换电源模块                  |
| 策略不生效   | ESP32 未更新策略    | 重启 ESP32 模块或手动上传策略          |
| 数据不上传   | 树莓派服务未运行    | 重新运行 `python web_api.py`           |
| 页面加载失败 | 后端/前端服务未启动 | 使用 systemctl / gunicorn 重新加载服务 |

## 八、远程访问与公网部署建议

- 使用花生壳、FRP 或 ZeroTier 等工具打通内网访问
- 公网服务器推荐采用 Ubuntu + 阿里云/腾讯云
- 设置 HTTPS 证书（Let’s Encrypt）保障安全性
- 配置防火墙开放 5000、80、443 端口

## 九、运维建议与升级策略

- 所有模块支持 OTA 远程升级（建议保留回滚机制）
- 建议采用 GitHub Actions 实现版本推送自动化
- 更新前自动备份配置与数据
- 采用语义化版本控制（SemVer），并撰写 CHANGELOG
